# ADR-0020: 应用与历史列表采用有界查询

- **状态**: accepted
- **日期**: 2026-09-10
- **来源**: 用户要求优化数据量增长后的性能，并确认目标为数百个应用、每个应用数百个制品。

## 决策

应用卡片、制品历史、发布历史统一使用 `limit` + 不透明 `cursor`，返回 `{ items, total, nextCursor }`。页大小为应用 24、制品 30、发布 20，接口允许 1–100。前端只挂载当前页，提供上一页和下一页；保留上一批内容直到新页到达，失败可重试或返回，输入停止 200ms 后查询。浏览器返回应用列表时，在查询缓存有效期内恢复该历史位置的页；切换搜索、产品、项目、平台、收藏或负责人条件时重新从首页读取。

服务端先做应用权限与全部筛选，再查询分页数据和总数。应用按名称升序或创建/更新时间降序，制品和发布按时间降序；所有顺序追加同方向的 UUID 作为唯一排序键。游标携带原始数据库精度的排序值及 ID，并绑定筛选范围；不通过 JavaScript Date 截断微秒。新增、删除不会产生 offset 位移；删除游标锚点后仍可继续。分页不是事务快照，浏览期间修改排序字段仍可能使记录跨页移动，刷新列表重读当前顺序。

目录计数使用 `/applications/summary`，只汇总当前用户可访问应用，返回产品/项目计数及可维护应用计数，不加载应用说明、成员头像或历史制品。产品管理页也使用该汇总；删除非空产品时进入筛选后的应用列表调整归属。

详情概览只查询最近 3 个制品以及单独标记的 latest 制品。即使 latest 在较早的历史页，也仍用它作为下载入口；没有标记时回落到最近上传。制品、发布页签在打开后才读取历史。界面总数来自应用汇总或服务端计数，不能用当前页长度替代总数。

应用列表的最近制品时间通过索引查单条记录，成员只补充当前页的应用。发布列表只汇总当前页 Release 的制品数量和类型；旧接口的逐发布 `filter` 改为一次分组。

## 搜索

依据 ADR-0006 的渐进策略，9 万条制品的全局搜索已达到需要索引的门槛（版本/无结果查询中位数约 0.7 秒）。将“制品自身字段匹配”和“所属应用字段匹配”分别先鉴权、排序、取 top K，再 UNION 去重并取整体 top K。

制品自身字段使用一个拼接表达式的 pg_trgm GIN 索引筛候选，然后保留原始逐字段条件复核，避免跨字段拼接误匹配。原有大小写、字面 `%`/`_`、权限、结果上限及字段返回约定保持兼容。普通用户的权限过滤必须在每条分支 LIMIT 前执行。

## 兼容与迁移

- 不传分页参数的既有集合接口仍返回原来的完整列表，兼容外部调用与现有选择器；页面主浏览路径改为分页。批量管理/分享所需完整目录延迟到打开时获取。
- 0024：应用排序索引，制品/发布的应用 + 时间 + ID 索引；替换被其覆盖的旧时间索引。
- 0025：安装 pg_trgm 并创建一个制品搜索表达式索引，不添加搜索服务或新 npm 依赖。
- PostgreSQL 16 的独立验证库和全部 PGlite 迁移测试均验证这些迁移。生产升级遵循 ADR-0008 的备份与预发布流程；GIN 建索引需安排合适维护窗口。

## 验证与边界

见 [容量测量记录](../performance-2026-09-10.md)。固定数据量校验返回上限、全局筛选/计数、权限、微秒精度、重复键、游标锚点删除、页内不累积 DOM、搜索分支去重和字段边界。容量测试脚本只允许显式命名的本地 `artifact_center_bench_*` 数据库，不清空业务库。

此决策解决主浏览旅程的全量读取。旧兼容接口和部分管理选择器仍可全量读取；单字符全局搜索的选择性较低，耗时高于完整版本号查询。尚不承诺并发容量、二进制传输速度或百万级元数据规模。
