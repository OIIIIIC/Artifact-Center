# ADR-0021: Linux 平台与制品文件格式分离

- **状态**: accepted
- **日期**: 2026-09-11
- **决策者**: 用户需求与工程实现

## 背景与问题

原 `zip` 同时表示 Application 平台和 Artifact 文件格式。仅将平台文案改为 Linux 后，前端对该平台的格式检查仍放行 APK/EXE，后端却拒绝发布；Linux 常见包格式也不在白名单内。

## 决策

- Application 平台使用 `android`、`windows`、`linux`。ZIP 仍是文件格式。
- Linux 接受 `.zip`、`.tar`、`.tar.gz`、`.tgz`、`.deb`、`.rpm`、`.AppImage`；TGZ 的制品类型归为 `tar.gz`，分发文件名保留原始扩展名。文件名匹配不区分大小写。
- `apps/api/src/lib/artifact-types.ts` 是无服务端依赖的领域注册表，浏览器通过 `src/lib/artifact-types.ts` 引用。网页文件选择、预检查、分片上传、旧版 multipart 上传和数据库类型使用一致的类型定义，落实 ADR-0009。
- 文件作为不可变二进制制品存储，不执行或安装 Linux 包，不从原生包内部自动解析版本。发布版本仍由用户确认，服务端计算大小与 SHA-256。
- 新迁移 `0026_linux_platform` 将平台枚举 `zip` 重命名为 `linux`，迁移工作台文本偏好；不修改 Artifact 的 ZIP 类型、文件名、存储路径、归属或历史版本。
- API 输入、旧筛选 URL、本地收藏筛选偏好兼容 `zip` 并归一化为 `linux`。旧分片会话的 `fields.platform` 在完成时同样归一化。发布工具新增 `linux` 并接受旧值。

## 验证与部署

- 浏览器上传逻辑测试覆盖全部 Linux 格式、错误平台文件与未知格式。
- 隔离数据库和临时文件目录的集成测试覆盖历史迁移、分片上传、发布、下载、文件名后缀、字节及 SHA-256 一致性，以及旧版上传接口。
- PostgreSQL 16 本地库已备份，并在备份恢复的独立数据库中演练迁移后再应用；原有 18 个应用和 13 个制品数量不变。
- 部署其他环境时，仍需先按 ADR-0008 完成备份和迁移，再启用新版本。
