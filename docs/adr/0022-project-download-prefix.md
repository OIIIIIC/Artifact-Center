# ADR-0022: 项目编码作为制品下载前缀

- **状态**: accepted
- **日期**: 2026-09-14
- **来源**: 用户要求同一项目下的应用统一使用项目下载前缀，例如十堰项目为 `shiyan_`。
- **更新**: ADR-0019 中项目不参与分发文件命名的约定；历史制品不可变规则继续有效。

## 决策

Project 增加可选的 Project Code，由管理员在“编辑项目”中维护。代码保存为小写，允许英文字母、数字及段间短横线，最多 64 个字符，同产品内唯一。项目名称与代码独立，重命名项目不改变编码。

新上传制品的 Distribution Filename 使用 `项目编码_应用编码_v版本_b构建号_渠道.扩展名`。项目编码未设置时兼容使用产品编码；迁移不猜测中文项目名称的拼音，不自动填写既有项目编码。项目编辑器显示生效规则及文件名示例。

两条上传路径共用相同命名函数。断点续传在创建会话时保存最终名称，后续修改编码不改写正在上传的会话。制品发布后的文件名保持不可变，修改编码或移动应用仅影响之后新建的上传；下载及分享继续使用制品保存的名称。

## 迁移与验证

新增 Drizzle 迁移 `0027_project_download_codes`，仅增加项目编码、校验约束和同产品唯一索引，不修改已有制品或存储路径。默认项目和旧客户端创建的项目编码为空，继续使用产品编码。

API 集成测试覆盖完整 SQL 迁移、管理员维护、格式及唯一性、两种上传入口、下载文件内容、同项目多应用前缀、上传会话命名冻结和历史名称保留。前端测试覆盖项目编码草稿、切换产品保留输入及保存值。
