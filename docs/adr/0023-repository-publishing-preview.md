# ADR-0023: 仓库绑定与确认后上传

- 状态：accepted
- 日期：2026-09-14

## 决策

Application 设置维护最多 20 条仓库发布绑定（克隆地址、精确分支、仓库内代码子目录）。旧 repository 展示字段保留，不自动推断绑定。迁移 0028 为已有应用设置空绑定。服务端生成 repositoryKey，忽略 SSH 用户与 HTTP/SSH 协议差异，保留主机端口和路径大小写。绑定不存凭据、命令或构建脚本。

发布目标查询在数据库内按绑定键、分支、目录和权限筛选，同时排除归档应用；返回所有匹配候选，超过上限明确失败，不能截断后选择目标。一个仓库可对应多个应用或产品，不允许默认选择多个候选之一。目录精确匹配，根目录为空；调用方使用应用代码所在目录。

本地 MCP 读取 Git remote、分支、提交和工作区状态。构建由宿主在本机执行，读取应用代码目录中的 artifact-center.release.json；仅声明检查/类型检查/构建命令、文件路径与版本来源，不需要 Application ID。平台不运行仓库命令，不成为 CI/CD 系统。

MCP 增加 match_repository 与 prepare_upload。prepare_upload 在成功构建后复制本地制品为独立临时快照，计算 SHA-256，并返回有效期 30 分钟的发布预览。upload_artifact 改为仅接收 planId 与 confirmed:true；宿主必须展示完整预览并等待一次用户确认，不能把最初的发布请求当作确认。确认后重新核对目标、Git 上下文和文件摘要，上传已确认快照，调用现有 verify 接口检查元数据、摘要、大小与可读性。成功接受的计划不能再次使用，校验失败报告制品 ID 供检查。

## 边界与兼容

这是 MCP 交互契约，不是平台级审批系统：确认来自宿主的人机交互，不能声称布尔参数证明人类身份。Release Credential 的服务端权限与渠道约束仍是授权边界；旧 CI 上传 API 不受新交互流程影响。

本决策补充 ADR-0017：新 MCP 上传必须经过预览与最终确认，仍固定 markLatest:false。稳定版上传需要明确正式发布意图；已有 beta 晋升工具的显式确认约束不变。latest 和删除仍在网站完成。

MCP 的 upload_artifact 输入为不兼容升级，需同步更新客户端与调用说明。平台先应用 0028 迁移并部署，再重新执行发布机器人页面提供的安装命令更新本机客户端。待确认计划仅在当前 MCP 进程有效；重启或过期后重新预览。临时快照定期清理，正常进程退出时删除；强制终止可能遗留操作系统临时文件。
