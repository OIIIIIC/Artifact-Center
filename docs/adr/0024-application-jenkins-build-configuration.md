# ADR-0024: 由应用配置 Jenkins 构建任务

- **状态**: accepted
- **日期**: 2026-10-13

Artifact Center 提供应用级构建入口，Jenkins 负责源码检出、依赖、编译和归档。构建配置属于 Application，构建结果只有经发布操作后才成为 Artifact。继续使用仓库中的 Jenkinsfile，不在制品平台维护任意 Shell 脚本或重新实现流水线引擎。

首阶段提供一个平台级 Jenkins 连接和每应用一个任务绑定，包含任务路径、普通参数默认值、归档产物匹配规则和启用状态。应用维护者可查看；平台管理员管理连接、修改绑定和校验任务，因为共享服务凭据不能让应用维护者随意调用其他应用的 Jenkins 任务。后续构建入口只能使用已绑定配置，仍需应用维护权限。

Token 以独立密钥进行 AES-256-GCM 加密，不进入响应或审计。允许管理员配置内网 HTTP(S) 服务；所有请求由后端发出，禁止重定向，限制响应大小与超时。地址或账号变化必须重新输入 Token，防止旧凭据转发到新服务。修改采用版本冲突检测。启用连接或应用配置前分别校验服务和任务；停用及禁用草稿可离线保存。

第一阶段只调用只读 Jenkins API，不触发构建、上传或部署。任务校验只检查 Pipeline 可构建状态及显式填写的普通参数；不代表构建权限、源码凭据、依赖缓存、产物匹配或真实编译已验证。多分支任务绑定具体分支子任务，当前不提供分支枚举或特殊编码分支路径。

第二阶段已实现应用内 Build Run、Build Output 和 Build Publication：持久化构建请求、队列 ID、构建号与实际提交，后台同步状态、按具体构建下载并导入制品。发布复用现有 Application 权限、版本、渠道、SHA256 校验与共享发布事务。构建成功不会自动成为发布；默认 beta，stable 需明确确认，均不自动标记 latest。

构建提交使用客户端请求键幂等和每应用活动构建唯一约束。提交前先持久化 submitting；请求超时/重启后只核对，不重复 POST。Jenkins 任务可声明保留 String 参数 `ARTIFACT_CENTER_REQUEST_ID` 以关联失去队列响应的请求；普通 API Token 的 cause 文本不能可靠关联。不支持该参数的任务仍可正常运行，但不确定提交保留 unknown 状态，重新发起需明确确认。

API 进程以数据库租约协调工作；构建与发布使用独立循环，导入不会阻塞状态更新。一次构建同一文件只成功导入一次。租约接管使用独立文件键，导入失败清理临时文件；制品、发布关联与审计同事务完成。下载票据限定用途并重查当前权限。日志保持纯文本、有限大小；产物仅取服务端构造的精确路径且禁止重定向。发布来源保存在 Artifact 的 buildMeta 中。

迁移 `0031_application_build_runs` 添加构建与发布表；没有自动改写 Jenkins 任务、配置真实账号或部署服务。接入步骤和边界见 [联动说明](../jenkins-integration.md)。
