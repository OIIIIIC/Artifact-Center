# ADR-0025: 同一次构建的产物分别发布到应用

- **状态**: accepted
- **日期**: 2026-10-13

同一 Jenkins 构建可以生成多个安装包变体，每个变体需要进入对应应用的制品历史。构建仍属于发起应用，不新增独立流水线导航。

管理员在应用构建配置中维护 `outputTargets: [{name, pattern, applicationId}]`。规则按 Jenkins 归档相对路径匹配，目标名称由服务端取应用名称。空列表沿用原来的当前应用发布；非空时每个待发布文件必须恰好匹配一个目标，否则拒绝发布。文件列表显示目标，发布请求不能指定或覆盖目标应用。

发起构建时将规则快照写入 Build Run。之后修改配置不改变历史构建的发布归属。Build Publication 保存目标应用 ID；原有记录为空时回退构建所属应用。发布前及传输完成后重新检查操作者对源应用和目标应用的维护权限，并验证目标未归档、文件类型符合平台。制品、存储路径、规范下载文件名和上传审计均归属目标应用，buildMeta 保留源应用和构建记录。

迁移 `0032_build_output_targets` 仅新增规则快照和目标外键。默认仍发布测试版，不自动标记最新；每个文件分别确认发布信息，同一构建同一文件保持幂等。

平台不解释 Flutter 依赖或 APK 内部业务变体。Jenkins 构建脚本负责名称、SDK、签名和版本验证；平台负责确定的产物路径到应用映射。真实设备功能验收仍由设备测试完成。

2026-10-20 补充：管理员删除 Application 时，在同一事务中先删除该应用自有 Build Run（级联清理自有 Build Publication），再删除应用，避免目标外键的 RESTRICT 阻止自有历史清理。目标应用若仍被其他应用的 Build Publication 引用，则返回明确的 409 并保留双方历史；不改变目标外键、不删除其他应用的制品。
