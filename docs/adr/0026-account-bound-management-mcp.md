# ADR-0026: 账号绑定的 MCP 管理能力

- 状态：accepted
- 日期：2026-10-20

## 背景与决策

用户要求把平台现有管理功能接入 MCP，并让权限跟随绑定账号。扩充平台发布凭据会把受限自动化凭据变成通用管理员凭据，也会与已有 CI 的权限预期冲突，因此新增独立的个人 MCP 凭据。

个人 MCP 凭据以 `acmt_` 为前缀，由已登录用户在网站“设置 → 个人 MCP 凭据”创建，绑定当前账号。只存 SHA-256 摘要，明文仅创建时返回，默认有效期 90 天，最多 365 天。用户可查看和单独撤销自己的凭据，不能查看或撤销别人的凭据。MCP 委托凭据不能再签发个人 MCP 凭据，也不能通过修改个人资料/密码取得新的浏览器 JWT。

每次 API 请求校验凭据有效期、撤销状态、账号存在性、启用状态及 tokenVersion，并读取当前账号角色。复用现有角色和 Application 成员校验，不建立 MCP 专属 ACL，不缓存凭据创建时的权限。密码、角色和启停变更沿用现有 tokenVersion 撤销策略；删除账号级联删除凭据。应用成员授权变更即时生效，无须重装客户端。

MCP 通过显式命名工具目录调用既有 REST 接口，接入账号、产品、项目、应用、成员、权限、制品、发布、分享、保留配置、发布凭据、审计、工作台及 Jenkins 连接/构建配置/构建记录。工具不允许调用方指定任意 URL、HTTP 方法或认证头。请求体由既有服务端 schema 校验，错误保留 code/status/details。秘密继续遵循原接口的只写、脱敏或仅创建时返回规则。

管理写操作复用原有审计，记录绑定账号及 `meta.source=mcp`，不记录凭据明文。审计仍沿用既有 best-effort 写入约定。客户端工具描述和 annotations 不作为授权边界。

## 兼容性与取舍

本决策扩展 ADR-0017、0018、0023 中对 MCP 的全局能力限制：**账号绑定凭据**可在现有服务端权限允许时删除资源、设置 latest 和执行管理动作；**原发布凭据 `acrt_`** 仍仅限发布接口，不获得任何管理能力。现有 7 个发布工具及构建后预览确认、快照校验、上传不自动设置 latest 的行为保留。主动设置 latest 使用独立管理工具，不改变上传默认值。

个人凭据的创建只能通过网站会话完成；MCP 可以列出、撤销自己的凭据。登录不是 MCP 工具，客户端不保存账号密码或浏览器 JWT。管理操作沿用现有 REST 语义，不增加平台级审批系统。

新增迁移 `0033_account_mcp_credentials`。部署前按仓库约定备份并完成预发布迁移演练，再部署 API/Web 并重新执行个人凭据页面的安装命令。旧凭据不会自动升级，旧 MCP 客户端需更新才能发现新增工具。

## 验证

真实 SQL 迁移及 API 集成测试覆盖摘要存储、跨账号隔离、撤销、过期、当前角色、停用、tokenVersion、应用成员权限变化、发布凭据隔离和审计来源。客户端测试覆盖管理凭据门槛、参数编码、请求体/查询转发、服务端 403 传播以及独立运行包工具发现。
