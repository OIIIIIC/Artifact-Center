# 默认应用首页进入优化（2026-09-11）

本轮覆盖登录进入默认应用首页、直接刷新首页、工作台刷新后进入应用三条路径。默认入口仍为应用页。

## 实现

- 登录提交时加载应用页代码；直接刷新首页时，代码加载与会话验证重叠。私有数据读取位于 AuthBootstrap 之后的已登录会话内。
- 页面代码加载与首屏准备分离。首屏应用（最多 24 个）、产品、项目、目录汇总和个人偏好复用正常页面的 QueryClient 与查询键，已有缓存不再重复请求。站内应用列表链接的鼠标、触摸和键盘意图也会触发准备；不预读全量制品历史。
- 高度过渡改为使用 ResizeObserver 提供的尺寸驱动 MotionValue，移除同步 getBoundingClientRect 和随后的 React 状态更新。仍使用 320ms 的高度过渡。
- 首次目录挂载无需写入零滚动位置；未展开产品的隐藏子菜单延迟创建。展开过的内容保留，让收起动画有完整节点。
- 卡片增加渲染复用，数据和回调引用未变化时跳过重复渲染；收藏、内容变化、路由、语言及用户状态仍能更新。

## 本机对照

Chromium、1440×960、真实 18 个应用，每种场景各两轮。下表为正式构建中到卡片 DOM 出现的均值，原始测量数据保留在本地忽略目录 `output/playwright/`。登录计时包含鉴权，刷新计时包含整个文档加载，工作台切入从点击计时，三类数值不可直接横向比较。

| 场景                 | 修改前 | 修改后 |
| -------------------- | -----: | -----: |
| 登录进入应用首页     |  682ms |  431ms |
| 直接刷新应用首页     |  772ms |  576ms |
| 工作台刷新后进入应用 |  386ms |  254ms |

这是本机小样本，工作区还有其他并行开发，存在时间波动；浏览器拦截会关闭 HTTP 缓存。偏好读写在隔离浏览器中保持一致，未向业务库写入容量测试数据。计时衡量结果节点出现，不代表动画完成时间或 INP。

**等待时间已有改善，但不能宣称首屏所有卡顿都已消除。** 最终样本仍有超过 50ms 的长任务，部分生产样本峰值高于修改前。当前证据支持保留已验证的预加载、同步测量移除和隐藏分支延迟创建；不足以保证任意设备稳定无掉帧，也不把单次最快结果当作性能承诺。

## 验证

- 前端 56 个测试文件、189 项测试通过；构建包含 TypeScript 检查，通过。修改文件 ESLint 检查通过。
- 高度组件测试在修改前捕捉到同步布局读取，修改后验证无需主动测量、收缩仍经过中间高度且卸载释放观察器。
- 目录测试在修改前发现未展开子菜单已创建，修改后验证延迟创建和收起时保留节点；既有搜索、定位、展开、项目应用缓存与页签测试保持通过。
- 首屏准备测试验证页面代码尚未就绪时数据已开始读取，实际 useApplications 消费预取缓存不会再次请求；不同范围隔离，清理会话后迟到结果不会恢复旧缓存。
- 浏览器四种卡片布局过渡均通过：192px 的收缩/展开分布在约 33～34 帧，430.5px 的整组移除/恢复分布在约 35～36 帧，最大单帧位置变化约 48px。
- 点击靠下的应用后，目录定位移动约 458px，分布在 38 个移动帧，最大一步约 66px。测试时保持页面前台；后台限速产生的无效测量未计入结果。

原始本地脚本与结果位于忽略目录 `output/playwright/`。本记录描述本地验证结果，不代表已部署到正式环境。
