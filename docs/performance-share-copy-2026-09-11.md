# 分享清单生成与复制的性能验证（2026-09-11）

用户反馈：生成并复制清单链接、成功提示出现时，现场本地 INP 为 368 ms。

## 发现与修改

本地对照结果指向分享弹窗的全屏 `backdrop-filter: blur(2px)`。在按钮进入生成状态、显示链接和出现成功提示期间，浏览器的画面呈现耗时明显高于点击处理函数自身。禁用成功提示或跳过兼容复制均未带来相同改善；移除模糊后，两组对照都明显降低了点击耗时。

分享清单弹窗改为半透明黑色遮罩，不再实时模糊整个页面。生成、复制、再次复制、成功提示和分享范围不变；其他弹窗未修改。

## 测试条件与结果

- 使用实际 ApplicationsPage、ShareCollectionDialog、Toaster 及生产 CSS，构建后在独立 Chromium 中运行。
- 2560×1430 视口，4 倍 CPU 降速；模拟 1000 个应用，当前项目 5 个应用，全部选中。
- 所有 API 均由测试拦截，生成接口固定延迟 80 ms，没有向业务环境创建分享。
- 模拟内网 HTTP 的 Clipboard API 不可用情况，执行实际 textarea / execCommand 兼容复制路径。
- 每组采样 3 次；数字来自 Event Timing 的 click duration，包含输入延迟、处理和呈现等待。它们不是整段请求耗时，也不是现场会话的最终 INP。

| 条件                                         | 三次点击耗时（ms） |
| -------------------------------------------- | ------------------ |
| 原实现，保留模糊、复制和成功提示             | 160 / 144 / 152    |
| 仅关闭成功提示                               | 248 / 168 / 192    |
| 跳过兼容复制，使用立即成功的替身             | 240 / 168 / 152    |
| 仅移除背景模糊                               | 72 / 64 / 64       |
| 第二组原实现                                 | 160 / 152 / 152    |
| 将模糊背景改为独立兄弟层                     | 248 / 160 / 152    |
| 第二组仅移除背景模糊                         | 80 / 64 / 64       |
| 最终修改：半透明黑色遮罩，保留真实复制和提示 | 72 / 72 / 64       |

最终修改的点击处理约 8–19 ms，复制相关同步操作合计约 1–4 ms，生成采样窗口内未观察到超过 50 ms 的主线程长任务。该结果支持减少画面呈现开销；没有声称复现或消除了用户现场精确的 368 ms。

## 回归验证

`node e2e/share-collection.mjs` 使用桌面和窄屏运行完整流程，并检查：

- 候选请求携带当前项目，只有 5 个应用；不加载全量目录。
- 生成请求包含正确的 5 项、名称和有效期。
- 返回链接与复制事件中的实际选中文本一致，成功提示显示。
- 再次复制复用原链接，不重复创建清单。
- 产品级候选支持后续页；弹窗可关闭，无页面异常。

脚本输出截图和 Event Timing 诊断数据到 `output/playwright/share-collection/`。耗时只用于诊断，不设依赖机器性能的固定通过阈值。部署后的实际设备仍需刷新页面后重新测量。
