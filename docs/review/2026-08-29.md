#### 问题 1：[P1] React Query 缓存未按账户隔离，切换账户后可能展示上一账户的应用与个人数据

文件：`src/store/auth-store.ts:57-60`、`src/lib/query-keys.ts:3-18`、`src/providers/query-provider.tsx:10-18`

退出登录只清除了访问令牌和 Zustand 会话，没有清空 React Query 的内存缓存；同时应用目录、应用详情、成员、审计和新增的个人工作台查询键都不包含用户 ID。全局查询默认保鲜 30 秒，因此用户 A 退出后由用户 B 在同一 SPA 会话登录，已有缓存可能被直接视为 fresh，短时间内展示 A 可访问的应用名称、成员、操作日志或收藏/最近访问数据，而不只是一次加载闪烁。后端仍会阻止越权写入，但前端已形成跨账户信息泄露。建议将账户 ID 纳入所有授权数据的查询键，并在登出、401 和账户切换时统一执行 `queryClient.clear()`；需要补一个 A 登录→加载私有数据→登出→B 登录的回归测试。

#### 问题 2：[P1] 演示数据刷新脚本没有环境护栏，会直接覆盖当前数据库中的应用与制品元数据

文件：`apps/api/src/db/refresh-demo-catalog.ts:323-345`、`apps/api/package.json:14`

`db:refresh-demo` 直接复用 `DATABASE_URL` 开启事务并执行批量 `UPDATE`，没有检查 `NODE_ENV`、数据库主机/库名，也没有要求显式的破坏性确认参数。只要目标库中存在匹配的地域和应用代码，运行该命令就会重写真实应用名称、包名、负责人、版本和历史制品信息。建议默认只允许本机开发数据库，并要求类似 `ALLOW_DEMO_DATA_RESET=1` 的二次开关；执行前打印目标库和变更预览，生产环境无条件拒绝。

#### 问题 3：[P2] API 质量门禁没有启动 PostgreSQL，迁移、约束、触发器和真实路由 SQL 均未被验证

文件：`.github/workflows/ci.yml:48-78`、`apps/api/src/routes/workspace.test.ts:1-47`

API CI 只运行类型检查、Vitest 和编译，没有数据库 service，也没有执行迁移。现有测试大量聚焦纯函数或 mock；例如新增个人工作台测试只覆盖序列化和 Zod schema，没有真正请求收藏、访问记录和偏好路由。数据库迁移、Drizzle 查询、事务回滚、唯一约束、制品摘要触发器以及权限与 SQL 的组合行为都可能在部署后才暴露。建议在 CI 增加一次临时 PostgreSQL 的 migrate + route integration 测试，优先覆盖上传完成、管理员移交、分享解析、访问授权和个人工作台。

#### 问题 4：[P2] 生产依赖审计存在高危告警，且脚手架 CLI 被放进运行时依赖

文件：`package.json:38-57`、`apps/api/package.json:16-26`

使用官方 npm registry 执行生产依赖审计时，根项目报告 8 个 high、3 个 moderate，API 独立锁文件报告 2 个 moderate。根项目中的多数高危传递依赖来自 `shadcn` CLI，但它目前位于 `dependencies`；实际浏览器依赖 `react-router-dom@7.18.1` 也命中 high 告警。API 的 Hono 与 Node adapter 存在可升级修复的中危告警。当前使用方式不一定触发每个漏洞，但 CI 没有审计步骤，风险会持续沉积。建议把 `shadcn` 移入 `devDependencies`，升级 React Router、Hono 与 adapter，并在 CI 增加明确的 audit 策略和例外说明。

#### 问题 5：[P2] `format:check` 当前失败，286 MB 的本地 pnpm store 未被忽略且不在 `verify` 中

文件：`.gitignore:16-25`、`.prettierignore:1-4`、`package.json:14-21`

工作区根目录存在未跟踪的 `.pnpm-store/`，共约 22,651 个文件、286 MB；它既未被 Git 忽略，也未被 Prettier 忽略。`npm run format:check` 因扫描 store 内的声明文件而报语法错误，而主 `verify` 和 CI 又没有运行格式检查，因此日常绿灯掩盖了失败。该目录也有被误加入提交或打包上下文的风险。建议忽略 `.pnpm-store/`，把格式检查加入 `verify`/CI，并确保插件检查也进入统一门禁。
