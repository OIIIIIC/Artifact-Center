## 分支 main

### 作者 oiiic

#### 问题 1（已修复）：Docker 构建遗漏新共享命名模块

`src/lib/artifact-filename.ts` 改为复用 API 的命名函数，但原 Dockerfile 只复制类型注册表，镜像构建实际失败并报 TS2307，无法解析 `apps/api/src/lib/artifact-filename`。

修复：Dockerfile 同时复制命名模块与类型注册表；前后端继续使用同一命名规则，不重新引入重复实现。修复后前后端 Docker 镜像构建通过。

#### 问题 2（已修复）：HTTP 内网创建产品依赖不可用的 randomUUID

`src/features/products/product-editor.tsx` 在提交时直接调用 `crypto.randomUUID()`。模拟内网 HTTP 缺少该方法后，实际表单测试出现未处理异常，创建接口没有发出请求。

修复：使用 HTTP 环境可用的 `getRandomValues` 生成 128 位随机产品编码。新增 `product-editor.test.tsx` 验证实际提交和保存回调；测试已从失败变为通过。

## 重点复查

- 权限：项目写接口仍要求管理员；普通用户可读目录元数据不等于获得应用读取或上传权限。分享活动保留应用级鉴权，测试覆盖第二个清单成员、历史撤销记录和越权拒绝。
- 数据兼容：0027 只增加可空的项目编码、格式约束和同产品唯一索引；旧项目默认空值回退到产品编码，不更新制品名称和存储键。
- 上传一致性：两条上传入口共用命名函数，断点续传创建时冻结最终名称；现有测试覆盖修改项目编码、移动应用、复合扩展名及历史文件内容。
- 失败路径：项目保存失败保留草稿；目录排序冲突回退；收藏失败仅回退相关应用。产品名和产品编码均有唯一索引，重复创建由服务端拒绝。

- 测试覆盖：新增精确时间的无效输入、补零和非整点时区测试。没有本次线上负载测试或全流程真实用户浏览器验证，不将这些声明为已完成。
