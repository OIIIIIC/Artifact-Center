## PostgreSQL 16 性能验证

独立本地数据库，完整应用迁移；300 个应用、90,000 条活动，其中 4,500 条成员快照分享、4,500 条旧分享事件及对应分享项。比较旧查询及原索引集与新查询及新增索引，返回的前 50 条 ID 和顺序完全一致。

| 指标                   |                修复前 |                                         修复后 |
| ---------------------- | --------------------: | ---------------------------------------------: |
| 三次热查询耗时（ms）   | 4.634 / 5.358 / 4.948 |                          1.185 / 0.945 / 0.860 |
| 最后一轮共享缓存块命中 |                 1,624 |                                          1,265 |
| 全站分享索引候选       |                 9,000 |                                              0 |
| 被过滤的无关日志       |                 8,970 |                                              0 |
| 目标应用候选           |          300 直接归属 | 300 直接归属 + 15 快照 + 15 旧分享，去重为 300 |

首次扩充旧分享数据后，普通 JOIN 仍扫描 4,500 条旧分享，缓存块命中从 1,624 增至 2,862，性能断言失败；改用按分享的索引查找后通过。该失败没有被简单重跑忽略。

原始计划：[performance-audit-2026-09-15.json](../performance-audit-2026-09-15.json)。复现脚本：[benchmark-audit.mts](../../apps/api/scripts/benchmark-audit.mts)。设置 `BENCH_DATABASE_URL` 为显式创建的空本地 `artifact_center_bench_*` 数据库，从 `apps/api` 运行 `npx --no-install tsx scripts/benchmark-audit.mts`；脚本拒绝非空库，不清理业务数据。

上述为本地数据库查询测量，不代表生产接口延迟或并发容量。没有部署或修改业务数据库；上线时需应用新增索引迁移并更新 MCP 客户端。
