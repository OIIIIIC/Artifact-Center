# 核心浏览器旅程

在正在运行的本地 Artifact Center 上，用独立 Chromium 会话验证：登录 → 搜索专用应用 → 上传并发布 Beta ZIP → 查看版本 → 登录下载 → 创建固定版本分享 → 未登录下载。两次下载均与上传源文件比较文件名、字节数和 SHA-256。

这是一条有真实前端、API、数据库和存储参与的成功路径，覆盖边界见 [feature-matrix.json](./feature-matrix.json)。它不代表全站、所有角色或所有制品类型已经通过验收。

已完成的本地运行结果见 [RESULTS.md](./RESULTS.md)。

## 执行契约

| 项目       | 约定                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------- |
| 目标       | 仅 localhost、127.0.0.1 或 IPv6 回环地址；默认 `http://127.0.0.1:5178`                               |
| 服务       | 使用已运行的开发服务；默认前端 `/api` 代理到 API 4001；必须通过数据库和存储就绪检查                  |
| 浏览器     | 默认无界面 Chromium；独立登录会话和独立匿名分享会话，不复用用户窗口                                  |
| 重启和重试 | 不重启服务，不自动重试失败用例；每次执行使用新的唯一标识和数据                                       |
| 身份       | 已有本地管理员测试账号，凭据仅来自环境变量；不修改账号、密码或角色                                   |
| 数据       | 复用现有启用的产品与项目，创建本轮专用 ZIP 应用、Beta 制品及一天有效的本地分享                       |
| 副作用     | 允许专用应用内发布、下载和分享；搜索引起的个人偏好变化在结束时恢复；审计事实按产品规则保留           |
| 清理       | `finally` 中按已登记 ID 和本轮名称前缀核验后删除专用应用，检查制品和分享失效，比较原有应用及制品库存 |
| 禁止事项   | 正式发布、操作既有业务制品、全局保留策略清理、发送链接到外部服务                                     |

API 仅用于就绪检查、专用应用准备、只读效果核验和清理；登录、搜索、上传发布、两次下载和分享创建由浏览器驱动，不模拟网络响应。

## 运行

先安装项目依赖与 Chromium：

```powershell
npm ci
npx playwright install chromium
```

本地数据库、API 和前端需预先运行。不要对已有数据执行重新初始化或种子脚本。可在各自终端运行：

```powershell
npm run dev:api
npm run dev -- --host 127.0.0.1 --port 5178 --strictPort
```

通过本地安全环境设置提供以下变量；不要把真实凭据写进测试源码、报告或 Git 文件。

| 变量                  | 用途                                                    |
| --------------------- | ------------------------------------------------------- |
| `E2E_AUTH_IDENTIFIER` | 必填，本地管理员测试账号                                |
| `E2E_AUTH_PASSWORD`   | 必填，原样传入账号密码                                  |
| `E2E_BASE_URL`        | 可选，默认 `http://127.0.0.1:5178`                      |
| `E2E_HEADED`          | 可选，`1` 表示显示独立浏览器窗口                        |
| `E2E_RUN_ID`          | 可选，6–48 位小写字母、数字和连字符；通常使用自动生成值 |

```powershell
npm run typecheck:e2e
npm run test:e2e:core
```

重复运行时再次执行测试命令。运行器的输出目录会被后续运行更新，比较两次结果前需分别保存本轮证据。不要同时对同一个账号运行多份测试，以免工作台偏好恢复互相覆盖。

## 结果与边界

产物写入 Git 已忽略的 `output/e2e/`：下载文件、发布和匿名分享页面截图、拥有权登记、下载摘要与清理结果。自动 trace、视频和失败页面截图关闭，以免记录登录凭据或分享能力令牌；本套件仅主动保存经过选择的页面证据。

判定应同时查看运行结果与清理证据：

- **通过**：浏览器旅程和两个文件校验通过，测试数据清理及原有状态核对通过。
- **产品失败**：有证据说明正确执行的用户操作或最终业务效果不符合预期。
- **测试失败**：定位器、断言、准备数据或清理实现错误；修正后重新执行，不能据此直接归因产品。
- **阻塞**：缺少账号、浏览器、服务、启用目录或必要权限；跳过不算通过。
- **未覆盖**：正式发布、APK/AAB/EXE、其他角色、失败重试与断点续传、集合分享、分享过期/主动吊销、多浏览器、移动端和 CI 隔离环境。

异常中止时，先查看本轮 `owned-data-*.json` 和清理报告。仅凭名称前缀批量删除旧数据不属于本套件的清理方式；恢复操作必须同时核对登记 ID 和当前对象归属。

开始操作专用应用前，原始工作台快照会保存到 Git 已忽略的 `.diagnostics/terra-core-e2e-workspace-<runId>.json`，正常恢复并核验后删除。该文件用于意外中止后的本地恢复，包含个人筛选内容，不应提交或复制到公开报告。进程被强制终止时不能保证自动清理完成。
